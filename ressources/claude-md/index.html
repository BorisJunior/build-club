01. Pourquoi c'est fort

Le vrai levier, c'est la memoire persistante

Le prompt du moment peut etre bon. Mais si ton agent n'a aucun cadre permanent, il peut rebasculer a chaque session dans un mode brouillon, pressa ou incoherent.

Un bon `CLAUDE.md` devient une sorte de garde-fou permanent. Il rappelle en continu comment travailler, quoi verifier et ce qu'on n'a pas le droit de bacler.

Memoire

Toujours relu par l'agent

Tu n'as pas besoin de repeter a chaque session "teste, verifie, respecte l'archi". Le fichier le fait pour toi.

Discipline

Une vraie definition de termine

Il ne suffit plus que le code existe. Il faut qu'il soit verifie, coherent et defendable.

Qualite

Checks et tests explicites

Tu peux y mettre les vraies commandes de ta stack, au lieu de laisser l'agent deviner ce qu'il faut verifier.

Structure

Conventions et architecture

Tu peux lui interdire de melanger les couches, de contourner la structure du repo ou de bricoler juste pour aller vite.

02. Ce que tu telecharges

Une base concrete, pas un modele vide

La base partagee ici n'est pas un vague rappel de bonnes pratiques. Elle garde le ton d'un vrai fichier de production : tests obligatoires, checks explicites, architecture, workflow et definition claire du travail bien fait.

Elle reste orientee Python propre et architecture serieuse. C'est volontaire. Ensuite, le prompt d'adaptation sert a la traduire dans ta propre stack.

extrait / base concrete 
## Exigences non negociables

- tests obligatoires
- checks verts avant de conclure
- pas d'over-engineering
- typage quand la stack le permet
- securite minimale

## Checks explicites

uv run black .
uv run ruff check .
uv run mypy .
uv run pytest tests -v

## Architecture

1. le domaine ne depend jamais de l'infrastructure
2. l'application n'importe pas l'infrastructure directement
3. l'infrastructure implemente les ports

## Workflow de session

1. comprendre
2. planifier
3. coder
4. expliquer
5. tester
6. verifier
7. corriger
8. conclure
03. Le prompt

Tu l'adaptes a ta stack, pas l'inverse

Le bon usage, ce n'est pas de copier ce fichier tel quel dans n'importe quel projet. Le bon usage, c'est de coller cette base dans ton IA avec le prompt ci-dessous pour lui demander de la traduire proprement dans ta stack.

Si tu es en TypeScript, Laravel, Go, Rust ou autre, le prompt sert justement a remplacer les commandes, les conventions et les references d'architecture par les bonnes pour ton contexte.

prompt-adaptation
